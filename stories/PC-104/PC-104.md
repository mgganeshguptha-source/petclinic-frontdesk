Title: Front-desk panel showing visits by status, read from the host app's shared store

Story: As a receptionist, I want a front-desk panel that shows how many visits are scheduled, completed or cancelled, and lists the scheduled ones by date and pet, so that I can plan the day without opening the clinic app's pages.

**Requires a new or changed contract from:** petclinic-angular-demo

Expected behaviour:
- This app runs on the same page as the petclinic host app (`petclinic-angular-demo`), which owns the visits data. It does **not** call the API. It reads the host's shared visits state through the host bridge defined in the attached store folder (`store/visits/visits-bridge.ts`): the current value on `window.petclinicHost.visits`, and updates via the browser event whose name is exported from that file.
- Use the attached files as the contract: the `VisitsBridgeState` and `VisitsBridgeVisit` interfaces and the event-name constant (`store/visits/visits-bridge.ts`), the status-count type `VisitStatusCounts` (`store/visits/visits.selectors.ts`) and the status values and labels (`visits/visit-status.ts`), exactly as they are defined there. Each bridge visit carries only `id`, `date`, `status` and `petId`. Copy the interface and the constant into this app (e.g. `src/app/host-bridge/`); do not invent fields that are not in the contract, and do not accept alternative shapes of the same data.
- Add a `HostBridgeService` that exposes the bridge state as an Observable: it starts with the current `window.petclinicHost.visits` (or "not available" when the host has not published yet) and emits on every bridge event.
- Add a "Visits by status" panel component to the app shell: one line per status — Scheduled, Completed, Cancelled, Not set — with its count from the bridge's status counts, and below it a list of the scheduled visits (date and pet ID).
- While the bridge reports `loading: true`, show "Loading visits…". When it reports an `error`, show the error text exactly as published (the host sends a fixed message). When the host has not published anything yet, show "Waiting for the clinic app…".

Acceptance criteria:
- AC1: `HostBridgeService` reads `window.petclinicHost.visits` on start and listens to the bridge event using the event-name constant from the contract; it removes the listener when destroyed.
- AC2: The types and the event name used by this app match the attached `visits-bridge.ts` exactly; no field outside `VisitsBridgeState` is read, and there is no fallback for a different payload shape.
- AC3: The panel shows the four counts with the labels Scheduled, Completed, Cancelled and Not set, taken from the bridge's status counts (not recomputed from the list).
- AC4: The panel lists only visits whose status is `SCHEDULED`, showing date and pet ID.
- AC5: The loading, error and "Waiting for the clinic app…" states show as described, and the page never throws when the bridge value is missing.
- AC6: `npm install … && npx ng build --configuration development` passes.
- AC7: Display rules. Scheduled visits are listed by date ascending, each showing the bridge's `date` string unchanged and "Pet <petId>" ("Pet: not set" when `petId` is missing). When no visit is SCHEDULED the list shows "No scheduled visits.". While `loading` is true only "Loading visits…" is shown; otherwise, when `error` is set, only the error text is shown; counts and the list show only when neither is se

In scope:
- `src/app/host-bridge/*` (contract types copied from the attachment, `HostBridgeService`), a panel component under `src/app/`, and `src/app/app.component.*` (show the panel).

Out of scope: calling the REST API, NgRx in this app (it only reads the host's bridge), module-federation wiring between the two apps, styling beyond plain HTML, unit tests (this repo runs build-only).
